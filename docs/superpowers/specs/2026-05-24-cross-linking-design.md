# Cross-Linking Design

## Problem

The v2 site content has almost no internal cross-references. Previous attempts at auto-linking (data-gen's `scc-auto-linker.py`) failed due to combinatorial ambiguity exceptions. A semi-manual approach of authoring links in the source document worked better but used a legacy link format and lacked pipeline support for link density control.

## Decisions

- **Source document is the link authoring layer.** Links are added to `Draw Steel Heroes.md` (and future input docs) using AI assistance, scripts, or manual editing — not auto-generated by the pipeline.
- **Full SCC codes as abstract identifiers.** Links use the `scc:` protocol with full codes: `[Text](scc:mcdm.heroes.v1/type/id)`. Each output format resolves these to concrete paths.
- **Source has the maximal link set.** Every instance of a linkable term gets an `scc:` link. The pipeline controls density on output.
- **Link density is a pipeline concern.** The resolver supports three modes: `all`, `first` (per extracted section), `none`.

## Source Document Format

Links in input documents use the full SCC code with the `scc:` protocol:

```markdown
[Fury](scc:mcdm.heroes.v1/class/fury)
[Gouge](scc:mcdm.heroes.v1/feature.ability.fury.level-1/gouge)
[dazed](scc:mcdm.heroes.v1/condition/dazed)
```

The existing ~2 links in the old colon-separated format (`scc:mcdm.heroes.v1:chapter:ancestries`) get migrated to the slash format to match the registry.

Link generation happens outside the pipeline via AI assistance. No auto-linker tooling in steel-etl.

## Link Resolution

### LinkMode Enum

The resolver gains a `LinkMode` parameter with three values:

| Mode | Behavior |
|------|----------|
| `all` | Resolve every `scc:` link to a concrete path (current behavior) |
| `first` | Resolve the first occurrence of each SCC code per section; strip subsequent occurrences to plain display text |
| `none` | Strip all `scc:` links to plain display text |

### Resolver Signature

```go
type LinkMode int

const (
    LinkAll   LinkMode = iota
    LinkFirst
    LinkNone
)

func (r *Resolver) ResolveLinks(content, relativeTo string, mode LinkMode) string
```

In `first` mode, the resolver tracks a `seen map[string]bool` scoped to each call (one call = one section/page). When it encounters an SCC code already in `seen`, it extracts the display text and returns it without the link wrapper.

In `none` mode, it always strips to display text.

## Output Generators

Each output generator declares its link mode. The mode can be overridden via CLI flags or config.

| Output | Default Mode | Use Case |
|--------|-------------|----------|
| `md-linked` | `all` | Full linked markdown for website/MkDocs |
| `md-linked` + flag | `first` | Cleaner reading, less link noise |
| `md` (plain) | `none` | Raw content without links (API, plain export) |

The mode is passed as a CLI flag (e.g., `--link-mode=first`). Future: `site.yaml` could specify a default link mode per section.

Resolution targets stay as-is: `SCCToFilePath()` converts SCC codes to relative `.md` paths. Future output formats (Obsidian, Foundry VTT) add their own path resolution strategy; the `LinkMode` filtering is format-agnostic and happens before path resolution.

## Unresolved Link Handling

When the resolver encounters an `scc:` link whose code isn't in the registry or doesn't map to an existing output page:

1. **Log a warning** with the unresolved code and the section it appeared in.
2. **Strip to plain text** — output just the display text, no link.
3. **Build succeeds** — unresolved links are not fatal.

This handles:
- **Typos** — visible in warning log, fix in source doc.
- **Cross-book references** (e.g., monster book not yet classified) — warnings expected; links activate when the book is added to the registry.
- **Stale codes** — graceful degradation if a code is ever invalidated.

## Scope

### In scope
- `LinkMode` enum and updated `ResolveLinks()` signature in `resolver.go`
- `first` mode deduplication logic
- `none` mode stripping logic
- Unresolved link warning + strip behavior
- CLI flag for link mode on relevant commands
- Migration of existing old-format links in the source document

### Out of scope (future)
- Auto-linker tooling in steel-etl
- Per-section link mode configuration in `site.yaml`
- Obsidian/Foundry VTT output format resolvers
- AI-assisted link generation tooling

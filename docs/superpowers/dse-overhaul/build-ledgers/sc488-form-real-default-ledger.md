## Spec (ticket description, verbatim, 2026-10-22)

> Found while fixing SC-483. Only reachable with authoring controls turned on (pref `authoringControls`, off by default).
>
> **Problem:** when a select field's key is absent from the block, the block edit form shows the first option in the list. For three fields that is not the value the block actually uses:
>
> * `ds-skills` `style`: the form shows `list`; the block renders as `ledger`.
> * `ds-roll` `mode`: the form shows `power-roll`; the block derives its mode from the expression (e.g. `roll: Might test` is a test).
> * `ds-roll` `difficulty`: the form shows `easy`; the block has no difficulty.
>
> The form's live preview also renders the shown value, so the preview does not match what Save writes. Since SC-483, Save no longer writes an untouched select, so the saved block keeps its real default. Only the form display and the preview are wrong.
>
> **Expected:** an absent select shows the value the block will actually use, and the preview matches the saved result.
>
> **Where:** `src/authoring/FormModal.ts`, the `select` case, which uses `field.enum[0]` as the fallback. A fix probably needs each element's parser default (or a schema `default`) to be available to the form.

## Design (owner decisions on the r0 survey, 2026-10-22) — the spec for r1

- D1. Every OPTIONAL select gets a leading sentinel option meaning "key absent" (non-empty sentinel constant, e.g. `'__dse-unset__'`, that never reaches data). Nothing is seeded into the working data for an optional select. Choosing the sentinel deletes the key from the working data. Validation, preview and Save all see the key absent, so the preview matches the saved result.
- D2. The sentinel's label is derived live from the element's own `parse()` (C2, generic — no per-element form code): the enum option `v` for which `parse({...working, key: v})` equals `parse(working without key)`. Exactly one hit -> `Default (<v>)`. Zero hits -> `Default (none)`. More than one hit, or parse throws -> `Default`. Recomputed on every revalidate (also when another field is invalid); keep the previous label on a throw. So roll mode reads `Default (test)` for `roll: Might test` and relabels to `Default (power-roll)` when roll: is edited to `Power Roll + Might`.
- D3. Label format is uniformly `Default (…)` — precedent: Scott's 2026-08-02 font-dropdown ruling (`src/prefs/fontStacks.ts:98-101`, `Default (Obsidian vault fonts)`). Stamina's `Default (default)` is accepted as-is (truthful; experimental surface). Wording is an owner call; shown to Scott in the land-ready comment as FYI, not a blocking ask.
- D4. Key present with a value: that option is selected and written as today; if the user picks the sentinel, the key's line is removed (a user action — does not conflict with SC-483).
- D5. Key present with null (`style:`): treated as absent — Default selected, Save drops the valueless line (today it writes `style: <enum[0]>`; rendering `style:` null is an error card).
- D6. REQUIRED select (none built-in): no sentinel; seed = schema `default` if it is in the enum, else enum[0]; always written (SC-483 required guard behaviour kept).
- D7. The SC-483 strip machinery (`untouchedSeeds` / `withoutUntouchedSeeds` / `currentBody(forSave)`) becomes dead under D1+D6 -> REMOVE it, with a comment pointing to SC-488. SC-483's jest cases stay as outcome pins (re-assert only the expectations the survey named: formModal.test.ts:398, :426 preview no longer sees a seed; :379-384 null key per D5).
- D8. Tests: new `describe('SC-488')` per the survey's list, plus a registry census test (every optional select on every registered element leads with the sentinel and its label equals the effective value of parse(absent)).

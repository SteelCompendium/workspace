# SC-408 S3: census of interactive surfaces across the plugin (sizing)

## Executive summary

- **Elements:** 22 registered. **13 ship in 7.0.0**: initiative, stamina-bar, montage, negotiation, counter, skills, feature, featureblock, statblock, characteristics, values-row, horizontal-rule, scc. **9 are deferred** (`deferred: true`, inert unless `experimental`): hero (also `hidden`), encounter, party, project, conditions, resource, surges, tokens, roll. 11 internal display-family cards render only through `ds-scc`.
- **Surfaces:** 37 interactive surfaces in total, 26 shipped and 11 deferred. This counts elements, modals, settings, the authoring and insert paths, chrome, link clicks, compendium sync, the write lifecycle, and the deferred sidebar host and form editor. No surface supports drag: grep found no `dragstart`, `drop` or `draggable` anywhere in `src/` or `main.ts`.
- **Estimated interactions (rough):** about 450 shipped and about 160 deferred, so about 610 in total. Of the shipped ~450, about 330 write the note or the vault. Rolling, collapse and the skills filter are session-only and never write.
- **Top 5 by risk:** (1) the `ds-initiative` tracker (~60 interactions, 15 of the last 300 commits are fixes to it); (2) StaminaEditModal (~40); (3) MinionStaminaPoolModal (the SC-417 bug cluster, 4 fixes); (4) ConditionsModal (~40, applies changes live); (5) `ds-montage` with its 3 modals (~55, no real-Obsidian coverage). Close behind: `ds-stamina-bar`, `ds-negotiation`, the settings tab, and compendium sync/migration (the only flow that moves vault files).
- **T1:** the initiative tracker and its 4 modals (StaminaEdit is the pilot, then MinionPool, Conditions, ResetEncounter), plus `ds-stamina-bar` with its recoveries strip and undo.
- **T2:** `ds-montage` with its modals, `ds-negotiation`, the settings tab, compendium sync/migration modals, and a small `ds-counter` top-up.
- **T3:** the editor-write authoring paths (insert commands, `/ds` suggest, schema autocomplete, compendium search+insert), chrome collapse/menu, feature rolling, statblock band/sticky header, skills, SCC link clicks.
- **T4/T5:** T4 is a render-smoke check for the near-static elements (characteristics, values-row, hr, `ds-scc`). T5 is the 9 deferred elements plus the sidebar and form editor, held back until 7.1.0 lifts the gate.

## Method and caveats

- **Shipped vs deferred.** Taken from `src/framework/registry.ts:202` (`deferred`), `isDefinitionHidden`/`isDefinitionDeferredOff` at `:211`/`:221`, `main.ts:290 registerFrameworkElementDefinitions`, and `grep deferred: true src/elements/*/definition.ts`. With the gate OFF, `activePrefDescriptors` (`src/prefs/catalog.ts:669`) also drops `authoringControls` and `printPreview`. That removes the form-editor pencil and print preview from the shipped settings.
- **Interaction counts.** One interaction is one distinct user action on one control, times its meaningful variants (± / typed / Enter / Esc / blur; enabled / disabled; read-only). Counts come from reading each view's listener and kit-control sites. They are sizing numbers, not edge-case inventories. The stamina-modal depth inventory is S1's job.
- **jest coverage.** Format: `suite (tests / dispatches)`. Dispatches is a grep count of `.click()` / `dispatchEvent` / `new *Event` in the suite. It is a proxy for how much the suite drives interactions rather than checking render output. Suites that click through a helper are undercounted.
- **Lifecycle coverage.** Scenario ids come from `visual-harness/obsidian-lifecycle.mjs` (25 scenarios). That gate tests the write lifecycle in real Obsidian: adoption, flush, click shield and click-away. It is not a behavior suite. The fixtures cover only `ds-counter`, `ds-initiative` (incl. StaminaEdit, Conditions and pool modal opened from it, G-S1/G-S2) and `ds-party`.
- **fix commits.** Format: `last-300 / all-time` (1,183 commits in total), counted by matching `fix` commit subjects against per-surface keywords. Treat the counts as a signal only. In the last-300 window, 60 of the 123 fixes are visual or theme work (SC-202/317/318/127/196/232/231), so the behavioral share is noted in the risk column.
- **Risk score.** Shipped (0/2) + writes note or vault (0–2) + interaction volume (0–3) + behavioral bug history (0–2). Maximum 9.

## Proposed rollout tiers

**Tier 1: shipped, writes the note, most interactions, live bug history.** These carry Scott's concern directly.
1. StaminaEditModal: the pilot (S1 is doing the depth inventory). Drive it both from `ds-stamina-bar` and from the initiative hero/creature rows.
2. MinionStaminaPoolModal: the SC-417 bug cluster from this week (death ladder, refused heal, detail-row rebuild).
3. ConditionsModal: about 40 interactions; live apply means every click writes.
4. The `ds-initiative` tracker: about 60 interactions, 15 recent fixes. Covers turns, pips, malice, captain, selection, title edit and reset, plus ResetEncounterModal (3 interactions, rides along).
5. `ds-stamina-bar` element: bar→modal, recoveries pips, Catch Breath, undo toast, popover editor. It has no real-Obsidian write coverage today.

Size: about 190 interactions.

**Tier 2: shipped, writes, mid complexity, or a high-consequence store.**
6. `ds-montage` and its 3 modals: about 55 interactions, no lifecycle coverage.
7. `ds-negotiation`: about 35 interactions (tabs, tracks, chips, checkboxes, reset).
8. Settings tab: about 45 controls. It writes data.json and every change must reflect live on rendered elements.
9. Compendium sync/migration modals: the only flow that moves or trashes vault files.
10. `ds-counter`: a small top-up only. The lifecycle gate already exercises it heavily.

Size: about 160 interactions.

**Tier 3: shipped; writes only through the editor, or interactive but session-only.**
11. Editor-insert paths: insert commands, `/ds` suggest, schema autocomplete, compendium search+insert (reference vs snapshot routing). Each needs one real-editor round trip.
12. Chrome collapse/expand and chrome menus across the 20 chrome-bearing elements; this can be table-driven.
13. Feature rolling (pref on), which statblock and featureblock inherit; the statblock villain band and sticky header; the skills unowned filter.
14. SCC link clicks in reading mode and the CM6 editor.

Size: about 90 interactions.

**Tier 4: shipped, near-static.** `ds-characteristics`, `ds-values-row`, `ds-horizontal-rule`, `ds-scc` and its display family. Run a render-smoke check plus collapse, which is mostly covered already by `npm run shots` and the jest render suites. About 10 interactions.

**Tier 5: deferred (behind `experimental`, not in 7.0.0).** `ds-hero` (~50), sidebar host, `ds-party`, `ds-project`, `ds-encounter`, form editor, `ds-conditions`, `ds-resource`, `ds-surges`, `ds-tokens`, `ds-roll`, print preview. About 160 interactions. Recommendation: write these tests as part of whatever un-gates each feature (7.1.0), so we do not spend effort on code that is not shipping. The one cheap exception is any harness work that already reaches them, such as party in G-S6h, G-S9c and G-S9e.

## C. Design
- `scripts/cdp-owned.mjs` (new): `proveCdpOwned({child, userDataDir, expectedPort?, timeoutMs=30000, pollMs, readFile, fetchImpl})` :87 polls OUR udd's `DevToolsActivePort` (parsed by `parseActivePort` :64, complete only with a full UUID line since the file has no trailing newline), then reads `GET http://127.0.0.1:<port>/json/version` and requires its browser GUID to equal the file's; throws `CdpOwnershipError` (:35) with `reason` `no-report | exited | port-mismatch | guid-mismatch | unreachable`. A pinned port that gets no report / a wrong port / a wrong guid says `port <n> ... another instance owns it`; port 0 without a report says `never reported a DevTools port` (no owner claim). Child exit -> `Obsidian exited during start-up` at once. `portInUse(port)` :43 = TCP connect probe on 127.0.0.1 and ::1 (any listener, not only CDP). No CDP command is ever sent by the helper.
- `visual-harness/obsidian-lifecycle.mjs`: header Env comment :118-121; `REQUESTED_PORT` :134 (unset = 0); pre-check :4634-4635 (validates the value, then `portInUse` for a pinned port only; message `port <n> is already in use — another instance owns it`); spawn with `--remote-debugging-port=${REQUESTED_PORT}` :4659; `proveCdpOwned` :4671 right after the spawn, mapped to `envFail`, BEFORE the page-target poll and `Cdp.connect`; the poll and the start line use the proven `PORT`, and `/json/list` is read on `127.0.0.1` (was `localhost`, which can resolve to ::1 first).
- Deviations/choices: (1) the file, not stderr, is the report channel (stderr would need `stdio: pipe` and a permanent drain; measured equal timing). (2) The pre-check now catches any TCP listener (was: an HTTP answer to `/json/version` only; a non-HTTP listener was missed, which (iii) needs). (3) The pre-check message changed from `already serves CDP` to `is already in use`. (4) Invalid `DSE_LIFECYCLE_PORT` values are an exit-2 usage error. (5) A pinned-port loser takes up to 30 s to report (silence is the only signal).
- Tests `test/unit/build/cdpOwned.test.ts`, 10 tests, node-subprocess pattern like `xvfbOwned.test.ts` (real HTTP server as fake browser, fake file, fake child): port 0 happy path (only `/json/version` requested); pinned happy path; pinned no-report with a stranger holding the port (0 requests to it, message names port + owner); guid mismatch; port mismatch; child exit (fast, not after timeout); port 0 timeout (no owner claim); half-written file waited out + `parseActivePort` shapes; unreachable reported port; `portInUse` on a non-HTTP listener.

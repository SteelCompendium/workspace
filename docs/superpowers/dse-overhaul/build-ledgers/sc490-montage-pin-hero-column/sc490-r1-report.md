## Opaque colours (decision 3) and how derived

Sampled off the rendered card beside the board (probe at 2x, fine, 12 rounds, 490px pane), then checked against the unpinned render: max difference 1-2 levels per channel in the name column.
- Name cells: dark `#23292d` (= card tone `#20262a` + the cell's own 1.5% white; the existing `var(--dse-sheen-soft)` gradient stays on top), light `#f8f9f9` (= card tone `#fafbfb` x 0.988).
- Corner: the existing `linear-gradient(180deg, rgba(0,0,0,.42), rgba(0,0,0,.26))` (light `.1 -> .05`) over the card's top-edge tone: dark `#21282b`, light `#fcfdfd`.
- Source gradient: `--dse-card-bg` = 160deg `#232a2e -> #181c1f` dark, `#ffffff -> #eef1f1` light.
- Edge rule: `box-shadow: inset -1px 0 0 var(--dse-metal-line)` (existing token; inset so no layout moves; no drop shadow). **No new tokens.** The solid colours are literals in the rule (documented in a comment), not custom properties.

## Sticky sub-pixel glitch (found while checking the crops)

At 1x and 2x, fine and coarse, dark and light: with `position: sticky` the pinned column's row divider sat 1 CSS px above the round cells' divider, with a 1px hole of card colour under it (rows are 67.83px tall; layout rects were identical — only pixels show it). It reproduces only when the row heights change AFTER the cell was already pinned (a fresh load at the final width is exact); `will-change`, `contain`, `transform`, `isolation` variants did not fix it, dropping and recreating the sticky box does. Fix: the ResizeObserver callback re-pins when a resize leaves the board overflowing (attribute off, one forced layout, on). Verified 16/16 configurations aligned (fine/coarse x dark/light x 1x/2x x rest/mid) after the fix vs 0/16 before. No `overflow: clip` needed (tried, removed). jest pins the re-pin sequence; the pixel check is scratch only (not a permanent test): `…/scratchpad/sc490-r1-impl/snap2.mjs`.

## 3. Footguns to add (measured at SC-490 r1)

- **Fresh worktrees have no `node_modules`** (`just wt-new` does not install). `cp -a <main checkout>/draw-steel-elements/node_modules <worktree>/draw-steel-elements/node_modules` (8 s, offline, package-lock identical) instead of `npm ci`; then `npm run harness:build` and `npm run host-css` once before any harness probe.
- **The harness's `#mount` is capped at 760px** (`visual-harness/vars.css`), so the board-scroll gate's "900px pane" is really 760px; a check that needs a wider pane must set `#mount`'s `max-width: none` as well as its width (the gate's board-fits step does).
- **Sticky cells and sub-pixel rows (Chromium):** a `position: sticky` cell that was already pinned when its row heights changed keeps painting its edges at the OLD sub-pixel offset: its row divider sat 1 device-independent pixel above the neighbouring cells' and left a 1px hole of card colour under it (rows are 67.83px tall here). A fresh pin, or anything that drops and recreates the sticky box, is exact. BoardView's ResizeObserver therefore re-pins (attribute off, one forced layout, on) on every resize that leaves the board overflowing. Anyone adding a sticky cell next to fractional-height rows should measure divider alignment against an unpinned render at 1x and 2x, fine and coarse.
- **`getBoundingClientRect` cannot see this class of bug** (layout rects are identical); only pixels can. The check used was: render with the pin on and with `data-overflow` removed, compare the pinned column's luminance column.
- **`npm run obsidian-lifecycle` and `npm run shots` background themselves past the tool's default 120 s timeout** if the Bash call has no explicit `timeout`; always pass `timeout` (up to 600000) on those calls.

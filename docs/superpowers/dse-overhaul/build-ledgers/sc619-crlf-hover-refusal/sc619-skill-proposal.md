## 1. "What `cardLinkLine` checks" (SKILL.md line ~449, under "Hover card writes (SC-594)"): add a sub-bullet

  - **A CRLF heading hover (SC-619, measured in Obsidian 1.15.1).** Obsidian cuts a heading HOVER's part (`getSectionInfo().text`, the card's `lineStart`) from ONE character after the heading line's content. In an LF note that character is the line break, so the part starts on the line under the heading (`"\n```ds-counter\n…"`, `lineStart` 1). In a CRLF note it is only the CR, so the part starts with a stray LF (`"\n\r\n```ds-counter\r\n…"`, `lineStart` 2): every line sits one lower, the every-line compare failed and the write was refused ("changed on disk first", nothing written) although nothing changed. A heading EMBED (part starts at the heading), a block hover / embed, and a whole-note hover / embed were never affected. `cardLinkLine` now drops that one LF and uses `relLine - 1`, only for a hover (`hovered !== null`) of a heading link (no `^id`) whose part starts with `\n` and whose heading line in the note ends in `\r\n`; the part is then compared exactly like the same LF note's, so every refusal (swapped names, a deleted adjacent twin, a moved section, SC-607 / SC-612 rules) is the same in CRLF as in LF. The condition reads the HEADING line's terminator (`eols[start]`), not the next line's: in a mixed note (CRLF heading line over an LF-only blank line) the part is `"\n\n```ds-counter\r\n…"` and the fix saves it. CR-only notes (SC-460) are measured (r3): the part starts with `\r`, the branch never fires, and they save and refuse exactly like the LF note (as at base). **Residual (accepted by the owner, option (a), under Scott's 2026-11-10 "Save nothing with a notice is fine"):** a CRLF note converted to LF from outside (git autocrlf, a sync client, an editor's EOL conversion) while its heading hover is open: Obsidian redraws the preview with the LF part but the card keeps the CRLF snapshot it was mounted on, and the drawn-from call of `cardLinkLine` reads the heading terminator from that snapshot, so the branch fires on an LF part and drops its legitimate blank line: + is refused with the Notice (base saved), not persistent: a preview reopened on the LF note (a new card) saves. So "an LF note never takes the branch" holds for a card mounted on an LF note, not for a CRLF-mounted card whose note became LF; the mirror (LF to CRLF while open) is refused at base and with the fix. Jest: `test/dom/framework/reading-mode-host-crlf-hover.test.ts` (23 tests: the 9 CRLF saves (incl. the mixed note), 7 LF/CRLF refusal parities, 4 controls, the model of Obsidian's slice, the 2 residual pins (refused; saved after reopening); its helper `hoverPart` slices at `heading end + 1` from the raw note, which is what a CRLF hover test must do, not `['', …].join('\n')`). Lifecycle `G-S112`.

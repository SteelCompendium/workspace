Design round done. Every docs GIF will be generated by `npm run docs-shots`, with no hand recording. No questions for you yet; I'll ask you to confirm the choices below together with the first before/after GIFs.

**Encoder (the ticket asked for this to be recorded here): `gifenc@1.0.3` + `pngjs@7.0.0`**, both pinned exactly as npm devDependencies. Both are MIT-licensed, small, and pure JavaScript, so `npm ci` installs everything. No system binary is needed.
- In a spike, the new initiative tracker GIF came out at 216 KB (1x) or 621 KB (2x), against today's hand-recorded 1.1 MB.
- ffmpeg was rejected for two reasons. On this machine it comes from Homebrew, not devbox, so a fresh clone + devbox wouldn't have it. It also turned one edge pixel of the red Malice number neutral grey.

**Repeatable output:** two runs produce byte-identical GIFs in both cameras. Two capture-only settings make this hold; they don't change the plugin. Without them, about 1 run in 3–6 differed by a handful of pixels. `docs-shots --check-stable` will enforce this.

**Which GIFs get made:** seven in total.
- **Browser camera:** initiative tracker, negotiation tracker, counter, and feature-card rolling.
- **Real Obsidian:** stamina bar + its modal, montage + its "Log an action…" sheet, and the initiative tracker's conditions modal. These three need Obsidian because their interaction is a modal.

**Five items from the ticket's list are deferred in 7.0.0.** SC-407 keeps deferred elements out of the docs, so these get no GIF now:
- `ds-encounter` and the sidebar handoff
- `ds-party`

In their place, "power roll" is covered by feature-card rolling and "conditions" by the initiative tracker's conditions modal. The deferred five are filed as SC-414 for when they un-defer.

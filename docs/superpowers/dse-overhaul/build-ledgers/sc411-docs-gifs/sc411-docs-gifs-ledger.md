## Scott's rulings (verbatim, dated)

### 2026-10-17 — the ticket itself (SC-411 description, Scott-authored)

> Every element in the plugin docs gets an animated GIF showing it in use, and every one of
> those GIFs is **regenerated by a command**, never recorded by hand.

> A hand-recorded GIF goes stale on the next landing, exactly the problem the docs manifest
> was built to end for stills. Extend the same rule to motion.

Scope (verbatim):

> 1. **A `gif` entry shape in `docs-manifest.mjs`**, alongside the existing `browser` /
>    `obsidian` shapes: an output filename plus a scripted interaction (a sequence of steps —
>    click this control, type this, wait for the write, hover that — with a capture after
>    each). `npm run docs-shots` runs the script, captures the frames, and encodes the GIF.
>    Same provenance rule as the PNGs: an image that cannot be regenerated by a command does
>    not belong in `docs/Media/`.
> 2. **Capture path.** Use whichever camera the element needs: the browser harness (Chromium,
>    deterministic, no display) for elements whose interactions are pure card interactions;
>    real Obsidian on a private Xvfb (`obsidian-camera.mjs` machinery) for anything that needs
>    the block write lifecycle, modals, the sidebar, or Live Preview. GIF encoding from PNG
>    frames with whatever is already in the toolchain or a small, pinned dependency — decide
>    and record in the ticket.
> 3. **One GIF per element**, covering its primary interaction. Minimum list, each at
>    steel-dark (Scott's docs theme choice — confirm in the first round):
>    * initiative tracker (replaces `initiative-tracker.gif`: edit title, mark a hero acted,
>      advance round, malice stepper, add an Amount row)
>    * negotiation tracker (replaces `negotiation.gif`; **supersedes** SC-388, which becomes
>      Duplicate/Canceled when this lands)
>    * counter / stepper
>    * stamina (bar + stamina modal)
>    * conditions (modal)
>    * montage
>    * power roll / roll
>    * encounter (`ds-encounter` handoff to the sidebar tracker)
>    * party award, surges, any other interactive element in `docs/` — enumerate from the
>      element registry in the first round and add to this list; static-only elements
>      (statblock, ability card) get no GIF.
> 4. **Docs wiring.** Each element doc page references its GIF the way
>    `docs/initiative-tracker.md` does today. README gets the initiative tracker one.
> 5. **Determinism and gates.** Frames must be stable across two runs (same frame count, same
>    key frames) or the capture is useless as a regeneration target. The `shots` / freeze /
>    parity gates must not move — `docs-shots` writes only to `docs/Media/`, never to
>    `visual-harness/shots/`. Keep file sizes sane (target under ~1 MB each; frame rate and
>    palette are the levers).

> ## Out of scope
> * Re-skinning or changing any element's behaviour. If a scripted interaction exposes a bug,
>   file it against the parent ticket.
> * Per-element GIFs for the site (v2) — plugin docs only.

> ## Acceptance
> * `npm run docs-shots` regenerates every GIF from scratch with no manual step; a fresh
>   clone + devbox can run it.
> * No hand-recorded GIF remains in `docs/Media/`; `docs-manifest.mjs` lists every one.
> * `docs/superpowers/dse-7.0.0-release-audit.md` updated: the SC-388 hand-record note is
>   replaced by this ticket.
> * Before/after pair for the two replaced GIFs posted inline on this ticket for review.

The r1 design (`sc411-r1-design.md` §B–F) is ADOPTED as the implementation spec, with these
rulings layered on top (they win where they differ):

- **O1 Encoder:** `gifenc@1.0.3` + `pngjs@7.0.0`, exact-pinned devDependencies. One global
  palette (255 colours + reserved transparent index), transparent-diff frames, dispose=1,
  palette built from SAMPLED pixels (not whole-frame concatenation — 607 MB RSS at 2x).
  Identical consecutive frames merge (delays add). ffmpeg rejected: linuxbrew-only here, and it
  turned a red Malice-digit edge pixel neutral grey.
- **O2 Element mapping (SC-407 deferrals win over the ticket's minimum list; Scott asked to
  confirm non-blocking):** 7 GIFs —
  browser: `initiative-tracker.gif`, `negotiation.gif`, `counter.gif`, `feature-roll.gif`
  (feature-card rolling = the ticket's "power roll"); Obsidian: `stamina-bar.gif`,
  `montage.gif`, `initiative-tracker-conditions.gif` (initiative's ConditionsModal = the
  ticket's "conditions (modal)"). **Parked (deferred in 7.0.0, no GIF, guard enforces):**
  encounter + sidebar, party, surges, `ds-roll`, `ds-conditions` → Backlog ticket **SC-414**
  (filed 2026-10-17, related to SC-411). Out of scope for every SC-411 round.
- **O3 Theme:** steel-dark (already the docs default in both cameras). Confirmation asked
  non-blocking.
- **O4 Browser camera runs with experimental OFF for gif entries** (harness `experimental=0`
  param) AND parks the real pointer before each capture — no deferred "Pin to sidebar" chrome
  in any frame. Default harness behaviour unchanged (no shot moves).
- **O5 Determinism knobs are runner-side only:** browser `--disable-partial-raster` +
  `animations: 'disabled'`; Obsidian freeze CSS + `.tooltip`/`.notice` removal + pointer
  parking. Dice via a seeded `Math.random` installed by the runner (init script / Runtime
  evaluate), not product code. `--check-stable` mode = capture twice, assert same frame count
  and byte-identical frame sha256s; exit 1 with indices/px/Δ on mismatch.
- **O6 Synthetic cursor ON by default** (the old GIFs showed a pointer; it shows the viewer
  where each click lands). One flag; Scott told in the ask.
- **O7 2x with budget fallback to 1x** (same rule as PNGs), budget 1,000,000 B per GIF.
- **O8 Folded in (same area, small):** route docs-camera error shots to
  `visual-harness/dist/docs-errors/` so `docs-shots` literally never writes `visual-harness/shots/`
  (ticket item 5); extend the deferred guard to refuse a `kind: 'gif'` entry for a deferred
  element from EITHER source (gif entries must carry `element`); add `nodejs@24` to the
  plugin's `devbox.json` (CI already uses node 24; today the plugin devbox falls through to
  host nvm v20 < engines 22.15) — this is what makes "fresh clone + devbox" true.
- **O9 Docs wiring:** each element page references its GIF like `initiative-tracker.md:7`;
  `negotiation-tracker.md` gains `negotiation.gif`; README gets the initiative GIF and its
  "two animated GIFs … recorded by hand" passage (`README.md:158-159`) is rewritten;
  `DOCS_MANUAL` shrinks to `favicon.ico`; `visual-harness/README.md` documents the gif shape,
  step vocabulary, `--check-stable`, and the determinism knobs; release audit lines 57/331
  replace SC-388 with SC-411; dse `CHANGELOG.md` gets an `## Unreleased` bullet.
- **O10 Split:** r2a = shared infra + encoder + the 4 browser GIFs + tests; r2b = Obsidian CDP
  driver + the 3 Obsidian GIFs + docs wiring. Same implementer (resumed). Then an independent
  review of the whole branch.

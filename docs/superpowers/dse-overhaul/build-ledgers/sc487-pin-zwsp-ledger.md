## Ticket (verbatim, 2026-10-22)

> In Live Preview, a block opened with ```` ```ds-counter ```` plus a zero-width space (U+200B) renders as the block. "Pin to sidebar" then:
> 1. writes a `_dse_anchor` into the user's note,
> 2. shows the "unavailable" card in the panel,
> 3. loses any save made from the panel.
>
> The cause: DSE reads the block type as `ds-counter` + U+200B (a zero-width space is not whitespace to JavaScript), which is not a registered type.
>
> Two parts to fix:
> * `requestPinToSidebar` should not stamp an anchor into the note for a type that isn't registered. It should show the one "can't pin" notice instead.
> * Decide whether the type reader should also stop at U+200B (and U+FEFF), and check what Obsidian renders for each.

Prior measurement (SC-457 r4 reviewer, real Obsidian 1.14.4): trailing U+200B — Reading view shows plain code, Live Preview renders the block, DSE language `ds-counter​`, LP pin broken on develop. Trailing U+FEFF — renders, language `ds-counter` (JS `\s` includes U+FEFF), writes and pins ok. Leading `﻿ds-counter` — not rendered, not claimed.

> **What discriminates, plainly (SC-472 r3, LOW-1).** (1) For (a) and (b) it is the 4 s busy spin, not the 8x CPU throttle: right after each write a `modify` listener spins `performance.now()` for 4 s (a slow handler of another plugin), so the redraw starts later than `PIN_TTL_MS` whatever order Obsidian's panes handle the write in. Anti-vacuity: the root left the document (one tracker) / a second root was drawn (two), the sizer was untouched until the redraw was let go, then collapsed and came back. A scroll that takes longer than 2.4 s is reported as environment (re-run): a correct build may then let go from its backstop. Every phase and write runs even after one fails; a FAIL line carries the screenshot.

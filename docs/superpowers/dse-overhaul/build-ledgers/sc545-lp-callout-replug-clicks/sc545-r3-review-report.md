## Findings

### MEDIUM-1: a card CodeMirror has taken out of the page at the toggle is neither saved for redraw nor redrawn; once scrolled back it stays dead
- Code: `src/framework/host/replugRemount.ts:82` (`if (!entry.root.isConnected || !inStickyWidget(entry.root)) continue;`). `inStickyWidget`, `:86-89`, also needs `closest('.markdown-source-view')`, which fails on a detached subtree. On the load side, `remountMarked`, `:194-211`, searches only the connected DOM of each leaf, and `hasUndrawnBlocks`, `:99-114`, sees only the cards that are in the page. Both run once, at layout-ready (`registerFrameworkElements.ts:87`).
- Scenario (P16a, `sc545-r3-probe-run3.json` and again in `sc545-r3-probe-run7.json`):
  1. `Probe3/topcallout.md` has a callout with a counter, then 200 paragraphs. Open it in Live Preview; + writes [6].
  2. Scroll to the end (scrollTop 9449). The card's root is now out of the page (`connected: [false]`), while the registry still holds it (`live 1, disconnected 1`).
  3. Turn the plugin off. Nothing is saved for redraw (`expando 0, attr 0`). Turn it on: the new instance's run reports `remounted 0, rebuilt []`.
  4. Scroll back to the callout. The card on screen is the tagged pre-disable root (`sameOldRoot: [true]`), owned by no live view. A real + click leaves the note at [6]. No error, no Notice.
- How far: P18 (`sc545-r3-probe-run8.json`). CodeMirror took the callout out of the page between scrollTop 1000 and 1250, in a 1021 px pane (the card's bottom was about 750-1000 px above the top of the view). So one screen away is enough. A long session note with trackers in callouts, scrolled past them while the user toggles or updates the plugin, hits this.
- Not a regression: base is dead in every case. But the ticket's "Expected: the click saves, or the card is redrawn so that it does" is still not met for this variant, and the CHANGELOG, architecture row and proposal all claim the redraw without this limit.
- Prescribed fix, all inside the ruled files:
  - (a) Stash side: do not require `isConnected`. Decide whether a card sits in a sticky widget from what the host learned at mount time (e.g. a flag set while the root was connected, as `lpCalloutSeen` / `livePreviewCalloutWidget()` already do for callouts, plus one for `.internal-embed`). Alternatively, use `root.closest('.cm-embed-block.cm-callout, .internal-embed')`, which works inside a detached widget subtree; drop the `.markdown-source-view` test for detached roots only.
  - (b) Load side: also remount on reattach. In the editor update listener that already runs on `viewportChanged` (`livePreviewReconcile.ts`, registered at `registerFrameworkElements.ts:77`), or in a sibling `EditorView.updateListener` from `ReplugRemounter`, query `update.view.contentDOM.querySelectorAll('[data-dse-replug]')` and run the same remount code for each one. Run the fallback check for that editor at the same point.
  - (c) Add G-S63 phase (h): callout off the page at the toggle, scroll back, then assert the card is redrawn, owned, + writes, and no rebuild.
  - If the owner instead files this as a follow-up, apply LOW-3.

### LOW-1: one stash that throws stops the whole run and leaves an unhandled rejection
- Code: `replugRemount.ts:199-207` has no per-element `try`, while `stashForReplug` has one at `:81-90`. `registerFrameworkElements.ts:87` uses `void replug.run()` with no `.catch`. `rebuildUndrawn` wraps only `rebuildView` (`:220-225`), not `hasUndrawnBlocks`.
- Scenario (P7g, `sc545-r3-probe-run2.json`): the stash is a Proxy whose getter throws. Result: `rejection: Error: forged … at readReplugStash … remountMarked … run … onLayoutReady … onload`. No remount, no fallback, so every card in every leaf stays dead; + writes nothing. The six realistic mismatches (v 2, empty ctx, unknown alias, numeric body, null, a V2 key only) all fall back cleanly (rebuilt 1, + writes, 0 errors). So this is robustness against a broken writer, not the shape check the ruling asks for.
- Fix: wrap the body of each element in `remountMarked`, and the check of each view in `rebuildUndrawn`, in `try/catch` that logs with `console.error` and clears that element's mark. Add `.catch(console.error)` at `registerFrameworkElements.ts:87`.

### LOW-2: the `disposed` check after the remount's await is untested (mutant E survives jest and G-S63)
- Code: `replugRemount.ts:220` (`if (this.disposed) return { remounted, rebuilt: [] };`). Removing it passes all 20 jest tests (`sc545-r3-mut-jest.log`, mutE). The jest test "off/on/off while a draw is running: … the fallback does not run" (`test/dom/framework/replugRemount.test.ts:229`) passes either way, because nothing is undrawn at that point. In real Obsidian the race happens: in P2c a disable queued as a microtask when the run started finished (13245.5) before the remount's draw did (13247.3).
- Scenario without the check: a disable during the remount, with a raw fence in some callout, makes the fallback run after the unload. The note is rebuilt while the plugin is off (raw code until the next enable) and loses its undo history.
- Fix: add a jest case. Put a raw DSE fence in a callout widget, start `run()` with a `mount` that resolves late, call `dispose()` before it resolves, then assert `setViewData` was not called.

### LOW-3: the CHANGELOG, architecture row and proposal claim more than the fix covers
- Superproject `CHANGELOG.md:11-16` (commit c590a35b): "The cards are now redrawn when the plugin is back on, so the click saves." This is false for MEDIUM-1. The bullet also does not say that the plugin update that ships this fix (an off/on, with the old build never saving the cards) redraws such notes whole once, which clears their undo history. P8 measured that path: rebuilt 1. Separately, `.repo-docs/architecture.md` (the `host/replugRemount.ts` row) and the proposal's G-S63 text have no "Not covered" line.
- Fix: if MEDIUM-1 is fixed, add only the update sentence. Otherwise also add "a card more than about a screen away from the visible part of the note when the plugin is turned off still needs the note reopened (follow-up SC-xxx)". Add the same to the architecture row, and a "Not covered" clause to the proposal sentence.

### LOW-4: a stale name in the module header
- `replugRemount.ts:12` names `rebuildViewsWithUndrawnBlocks`, which does not exist. The code is `ReplugRemounter.rebuildUndrawn` / `rebuildView` (`:166`, `:213`). Fix: rename it in the comment.

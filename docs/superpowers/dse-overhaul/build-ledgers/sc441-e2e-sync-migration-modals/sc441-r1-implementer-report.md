## Mechanics answers for phase B

**(a) Fixture release, no network, no product change.** `CompendiumSyncService.requestUrlFn` is a constructor-defaulted field the SC-440/SC-443 drivers already overwrite page-side (`s.requestUrlFn = …`, guarded by `__e2eStubbed`). The sync makes exactly two request shapes: `GET https://api.github.com/repos/SteelCompendium/data-unified/releases/latest` (or `/releases/tags/<tag>` when the Release setting is set) answered with `{status:200, json:{tag_name, assets:[{name:'md-dse-unified-en.zip', url}]}}`, then `GET <asset url>` answered with `{status:200, arrayBuffer:<zip>}`. New `e2e/driver/sync.ts` `fixtureRelease.install({ A:{…}, B:{…}, latest:'A' })`: the zip is built **Node-side with `fflate.zipSync`** (a devDependency already used by jest) from a hand-picked 4-6 file map per tag, base64'd into the page, decoded to an `ArrayBuffer` page-side; the stub keys on URL (`/latest`, `/tags/<t>`, `https://assets.example/<t>.zip`), records every URL (`calls()`), and has switches for lookup status (503/404), download status, a broken zip, an empty asset and a **gate** that holds the lookup (to keep a sync in flight). Tag A → B gives: update (changed file), upstream removal (file only in A), new file (only in B), unchanged. Proof it needs nothing else: `test/fakes/syncHarness.ts` `ReleaseServer` does exactly this in jsdom and the 64-test flow file passes over it (also `compendiumSyncRelease.test.ts`). Reuse the SC-440 `releaseStub` guard flag (`__e2eStubbed`) so `openSettings`/`openEditor` do not re-guard over it; a plugin reload gives a fresh service, so the stub goes in again per test.

**(b) Legacy fixture, and reaching Stop through real input.** Node-side the spec imports the same `src/data/migrationMap.json` and takes the first 25 entries (all real old → new paths), writes each through page-side `app.vault.create` (so Obsidian indexes them and its link cache sees them) with content `legacy <old path>`, plus: one unmapped user note inside the root, one user note OUTSIDE the root `Journal.md` containing `[[<one moved file's basename>]]` (for the link rewrite), one pre-occupied destination (a blocked rename) and one refused rename (page-side `renameFile` wrapper that throws for a chosen path, for the "failed" list). With the real map every fixture file is `modified:true|null`, so all are backed up (the backup path is exercised every time). To also cover "No backup folder is needed" (pristine) I would, page-side, set `plugin.migrationService.mapOverride` to the real map with the hash prefix of 2-3 chosen entries recomputed for the fixture bytes (real paths, patched hashes; test-side wrapper, no product change); say if you would rather skip that scenario. **Stop**: a run of 25 files is milliseconds, so a page-side wrapper holds the Nth `app.fileManager.renameFile` call (or the Nth backup `app.vault.createBinary` for a Stop in the backup phase) on a promise the test releases; the test then does a **real click / Enter / Space on `migration.running.stop`**, then releases. The wrapper is the only non-real part, as O7 allows; it is removed by a plugin reload or an explicit unwrap in the driver. The error screen is reached by a page-side `plugin.migrationService.execute = async () => { throw … }` (the engine swallows its own bookkeeping errors, so no real input reaches it).

**(c) The file-tree snapshot helper.** Node `fs` on the vault copy (not the vault adapter): `browser.getVaultPath()` (wdio-obsidian-service's openVault capability) walks every file under it, **dot-folders included** (`.trash/`, `.obsidian/plugins/draw-steel-elements/{data.json,compendium-manifest.json,compendium-migration-state.json}`), recording path → {size, sha256}; text on demand. Reasons: it sees what Obsidian does not index and does not depend on the plugin's own vault API; the volatile files (`.obsidian/workspace.json`, `app.json` which `setConfig` rewrites, `appearance.json`, the staged plugin `main.js`/`styles.css`/`manifest.json`) go in a small named allowlist, everything else must match. `diff(before, after)` returns created / removed / modified, and infers moves (a removed and a created path with the same hash). Wait before the "after" snapshot: `syncService.isBusy() === false`, registry write-idle, and two consecutive snapshots equal (a polled state, no sleep). **What the runner's reset does today** (`dse.openNote` → `closeEverything()` + `resetFixtures()`): rewrites changed fixture notes, recreates missing ones, `vault.delete(f)` for every INDEXED file not in `e2e/vaults/shipped/` (hard delete).

**Goal:** Convert all authored sub-repos to git submodules of the workspace superproject, keep `data/` as floating regenerable scratch, and add `just` recipes for isolated per-agent worktree environments, multi-machine sync, finishing, and an adapted deploy.

**Architecture:** The `workspace` repo becomes a superproject pinning 8 authored sources as submodules (`steel-etl` already is; add 7 more). Generated `data/` stays `.gitignore`d and is rebuilt by the pipeline per environment. Per-agent isolation is a workspace worktree under a sibling `worktrees/` dir, with submodules checked out on per-env branches and an empty scratch `data/`. Pipeline configs use sibling-relative paths, so each env resolves its own paths with zero config edits.

**Tech Stack:** git submodules + worktrees (git 2.43), `just` 1.52 recipes (bash shebang), devbox-wrapped Go/mkdocs, steel-etl pipeline.

### Task 6: Add `wt-new`, `wt-rm`, and `wt-status` recipes

**Files:**
- Modify: `justfile` (append the three recipes)

**Interfaces:**
- Produces:
  - `just wt-new <name>` — creates `../worktrees/<name>`, inits submodules, branches superproject + every submodule to `<name>`, makes scratch `data/`.
  - `just wt-rm <name>` — guards against uncommitted work, removes the worktree, deletes per-env branches, prunes.
  - `just wt-status <name>` — shows superproject + per-submodule ahead/pending-bump state.

- [ ] **Step 1: Append the three recipes**

```just
# Create an isolated environment for an agent/task: a workspace worktree under
# ../worktrees/<name> with all submodules on a branch named <name>, plus a
# scratch data/ dir. Submodules are branched (not left detached) so commits are
# never lost. See docs/worktrees-and-submodules.md.
wt-new name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    name="{{name}}"
    wtroot="$(cd "$root/.." && pwd)/worktrees"
    wt="$wtroot/$name"
    if [ -e "$wt" ]; then echo >&2 "[ERR] Env already exists: $wt"; exit 1; fi
    mkdir -p "$wtroot"
    git -C "$root" worktree add -b "$name" "$wt"
    git -C "$wt" submodule update --init --recursive
    git -C "$wt" submodule foreach "git checkout -b '$name' 2>/dev/null || git checkout '$name'"
    mkdir -p "$wt/data"
    echo >&2 "[INFO] Environment ready: $wt (branch: $name)"

# Tear down an environment created by wt-new. Refuses if the superproject or any
# submodule has uncommitted changes; deletes the per-env branches afterward.
wt-rm name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    name="{{name}}"
    wt="$(cd "$root/.." && pwd)/worktrees/$name"
    if [ ! -d "$wt" ]; then echo >&2 "[ERR] No such env: $wt"; exit 1; fi
    if [ -n "$(git -C "$wt" status --porcelain)" ]; then
        echo >&2 "[ERR] Uncommitted changes in $name (superproject); commit or discard first."; exit 1
    fi
    if ! git -C "$wt" submodule foreach 'test -z "$(git status --porcelain)"' >/dev/null 2>&1; then
        echo >&2 "[ERR] Uncommitted changes in a submodule of $name; commit or discard first."; exit 1
    fi
    git -C "$root" worktree remove "$wt"
    git -C "$root" branch -D "$name" 2>/dev/null || true
    git -C "$root" submodule foreach "git branch -D '$name' 2>/dev/null || true" || true
    git -C "$root" worktree prune
    echo >&2 "[INFO] Removed env: $name"

# Show what an environment has that isn't yet on its tracked branches: which
# submodules are ahead and whether the superproject has pending pointer bumps.
wt-status name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    name="{{name}}"
    wt="$(cd "$root/.." && pwd)/worktrees/$name"
    if [ ! -d "$wt" ]; then echo >&2 "[ERR] No such env: $wt"; exit 1; fi
    echo "== submodules ahead of their tracked branch =="
    git -C "$wt" submodule foreach '
        tracked="$(git -C "$toplevel" config -f .gitmodules submodule.$name.branch || echo main)"
        ahead="$(git rev-list --count origin/$tracked..HEAD 2>/dev/null || echo "?")"
        echo "  $name: $ahead commit(s) ahead of origin/$tracked"' || true
    echo "== superproject pending pointer bumps =="
    git -C "$wt" status --porcelain -- . | grep -E '^ M|^M ' || echo "  (none)"
```

### Task 7: Add `sync` recipe

**Files:**

**Interfaces:**
- Produces: `just sync` — fast-forward the current branch (if it has an upstream) and move every submodule to its newly-pinned commit.

- [ ] **Step 1: Append the `sync` recipe**

```just
# Bring this checkout into lockstep with origin: pull the superproject (if the
# current branch tracks an upstream) and move every submodule to its pinned
# commit. Submodules end in detached HEAD at the pinned commit -- that is normal
# for consuming a version; branch (via wt-new) only when editing.
sync:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    cd "$root"
    if git rev-parse --abbrev-ref --symbolic-full-name '@{u}' >/dev/null 2>&1; then
        echo >&2 "[INFO] Pulling superproject..."
        git pull --ff-only
    else
        echo >&2 "[INFO] No upstream for current branch; skipping superproject pull."
    fi
    echo >&2 "[INFO] Updating submodules to pinned commits..."
    git submodule update --init --recursive
    echo >&2 "[INFO] In sync."
```

### Task 8: Add `wt-finish` recipe

**Files:**
- Modify: `justfile` (append `wt-finish`)

**Interfaces:**
- Consumes: an env created by `wt-new`.
- Produces: `just wt-finish <name>` — locally merges each ahead submodule's `<name>` branch into its tracked branch, then bumps pointers and merges the superproject `<name>` branch into `main`. **Pushing is left explicit** (printed instructions) so the user reviews locally first — a deliberate refinement of the spec's "merge and push," matching the solo "review locally, then merge" workflow.

- [ ] **Step 1: Append the `wt-finish` recipe**

```just
# Land an environment's cross-repo work locally (no push): for each submodule
# with commits on branch <name>, fast-forward/merge it into the submodule's
# tracked branch; then bump pointers and merge the superproject <name> branch
# into main. Review, then push (the recipe prints the exact push commands).
wt-finish name:
    #!/usr/bin/env bash
    set -euo pipefail
    root="{{justfile_directory()}}"
    name="{{name}}"
    wt="$(cd "$root/.." && pwd)/worktrees/$name"
    if [ ! -d "$wt" ]; then echo >&2 "[ERR] No such env: $wt"; exit 1; fi
    if [ -n "$(git -C "$wt" status --porcelain)" ]; then
        echo >&2 "[ERR] Commit or discard changes in $name first."; exit 1
    fi
    pushed_repos=()
    # 1. Merge each ahead submodule into its tracked branch (local only).
    while read -r sm; do
        [ -z "$sm" ] && continue
        tracked="$(git -C "$wt" config -f .gitmodules "submodule.$sm.branch" || echo main)"
        ahead="$(git -C "$wt/$sm" rev-list --count "origin/$tracked..$name" 2>/dev/null || echo 0)"
        if [ "$ahead" -gt 0 ]; then
            echo >&2 "[INFO] Merging $sm: $name -> $tracked ($ahead commit(s))"
            git -C "$wt/$sm" checkout "$tracked"
            git -C "$wt/$sm" merge --no-ff "$name" -m "merge $name into $tracked"
            pushed_repos+=("$sm:$tracked")
        fi
    done < <(git -C "$wt" submodule foreach -q 'echo $name')
    # 2. Bump pointers in the superproject worktree and merge into main.
    git -C "$wt" add -A
    git -C "$wt" commit -m "chore: bump submodule pointers for $name" || echo >&2 "[INFO] No pointer changes"
    git -C "$root" checkout main
    git -C "$root" merge --no-ff "$name" -m "merge $name into main"
    echo >&2 "[INFO] Landed locally. Review, then push:"
    for pr in "${pushed_repos[@]}"; do
        sm="${pr%%:*}"; br="${pr##*:}"
        echo >&2 "    git -C $root/$sm push origin $br"
    done
    echo >&2 "    git -C $root push origin main"
    echo >&2 "[INFO] Then: just wt-rm $name"
```

- [ ] **Step 1: Create `docs/worktrees-and-submodules.md`**

```markdown
# Worktrees & Submodules — Cheatsheet

The workspace is a **superproject**: it pins exact commits of the authored
sub-repos (`steel-etl`, `v2`, `steelCompendium.github.io`, `data-sdk-npm`,
`data-gen`, `compendium`, `draw-steel-elements`, `statblock-adapter-gl-pages`)
as **submodules**. `data/` is *not* pinned — it is regenerated by the pipeline.

## Mental model

- A **submodule** = the superproject remembers "this sub-repo is at commit X."
- A **worktree** = the same repo checked out in another folder on another
  branch, sharing one history. We use one worktree per parallel agent/task.

## First-time setup on a machine

    git clone --recurse-submodules git@github.com:SteelCompendium/workspace.git
    cd workspace && just bootstrap   # idempotent catch-up

## Everyday commands

| Goal | Command |
|---|---|
| Sync this checkout to origin | `just sync` |
| New isolated env for a task | `just wt-new <name>` |
| What has my env changed? | `just wt-status <name>` |
| Land env work locally | `just wt-finish <name>` (prints push commands) |
| Remove an env | `just wt-rm <name>` |

Environments live in `../worktrees/<name>/` (sibling of `workspace/`).

## The two-commit rule (read this twice)

Changing a submodule is **two commits**:

1. Commit *inside* the submodule (e.g. in `worktrees/foo/v2`).
2. Commit in the **superproject** recording the new pointer (`git add v2`).

If you skip step 2, the superproject still points at the old commit and your
change "disappears" on other machines. `just wt-status` and lazygit's
Submodules panel show pending bumps so you notice.

## Detached HEAD is normal (when consuming)

After `just sync` / `git submodule update`, submodules sit in **detached HEAD**
at the pinned commit. That is correct for *using* a version. Only **edit** in an
env created by `wt-new` (which branches every submodule for you) so commits are
never lost.

## After `main` moved while you were working

    just sync                       # in the main checkout
    # in your env, rebase the env branch onto the new main as needed

## Driving it from lazygit

- **Worktrees panel** (`w`): create/switch/remove worktrees visually.
- **Submodules panel**: `enter` a submodule to operate inside it; the
  superproject view shows a pending pointer change to stage (the two-commit
  rule, made visible).

## Deploy

Deploy/publish happens **only on `main`**, serialized, from the main checkout —
never from an env. `just deploy` regenerates, pushes generated content into the
`v2`/org-site submodules, and bumps their pointers. Feature branches may run
`gen` to verify but write only to their own scratch `data/` and never publish.

## Gotchas

- `data/` is scratch: never `git add` it in the workspace (it is gitignored).
- `wt-rm` refuses to delete an env with uncommitted work — commit or discard
  first.
- Single remote: `origin` → SteelCompendium. There is no `fork` remote.
```

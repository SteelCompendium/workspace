# Feature Browser Subclass Filtering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add subclass filtering to the v2 Feature page's Search & Filter surface, presented as a merged Source facet where each class chip carries its subclasses as nested class-scoped sub-chips — and fill the one data gap by annotating the Summoner's four circles.

**Architecture:** Two independent workstreams. (A) Annotate the 20 Summoner circle-specific features in the steel-etl source with `@subclass` (parsers already read it; no code change). (B) In the v2 front-end, extract pure source/subclass model + matching logic into a testable `steel-feature-browser-core.js` (UMD, Node-tested), then wire it into `steel-feature-browser.js`'s `mount()` to render one merged "Source" facet (class chips + nested subclass chips) and match them as a single OR-group. The JSON data island already carries `subclass`, so B needs no pipeline change.

**Tech Stack:** Go (steel-etl, source content only — no Go edits), vanilla browser JS (IIFE + UMD core), Node's built-in `node:test` runner, CSS, MkDocs Material, devbox toolchain.

## Global Constraints

- **Isolated worktree only.** Both `steel-etl` and `v2` submodules are edited. Do all work in one worktree created with `just wt-new <name>` from the workspace root; never edit the shared main checkout. Land with `just wt-finish <name>` **after Scott reviews** — not as part of any task.
- **Never hand-edit generated output** (`v2/docs/Browse/`, `data/`). They are regenerated by the pipeline; regen during verification is fine but is never committed here (deploy recipes own that).
- **Devbox for all Go/Node commands.** Go and Node are not on PATH. Wrap every Go/Node command: `devbox run -- bash -c '<cmd>'` from the workspace root.
- **No AI attribution in commits** (no `Co-Authored-By: Claude`, no "Generated with…"). Per-task commits live in the submodule repos (steel-etl for Task 1; v2 for Tasks 2–4).
- **Subclass selection is class-scoped.** A subclass chip's filter value is the composite `klass + SEP + subclass`, so identically-named subclasses under different classes (e.g. Censor vs Conduit "Creation") are independent.
- **Deploy is separate.** `just deploy-v2` is Scott's explicit call, not part of this plan.

## Task 2: Source/subclass model + matching core (TDD)

**Files:**
- Create: `v2/docs/javascripts/steel-feature-browser-core.js`
- Test: `v2/tests/steel-feature-browser-core.test.js`

**Interfaces:**
- Produces (consumed by Task 3 via the `window.SCFeatureBrowserCore` global):
  - `SUB_SEP: string` — composite separator (`"§"`).
  - `subKey(klass: string, subclass: string) → string` — `klass + SUB_SEP + subclass`.
  - `buildSourceModel(items: Item[]) → { classes: {klass: string, subclasses: string[]}[], plain: {klass: string, source: string}[] }` — classes (source `"class"` with ≥1 subclass) sorted by source rank then name, each with its subclasses sorted; all other sources (incl. subclass-less classes, ancestries, kits, other) in `plain`.
  - `matchesSource(item: Item, selKlass: {[k]:true}, selSub: {[compositeKey]:true}) → boolean` — true if no source selection, or item's klass is selected, or any of item's class-scoped subclass keys is selected.
  - `Item` is the island shape: `{ klass?, source?, subclass? (string | string[]) , … }`.

- [ ] **Step 3: Write the core module**

Create `v2/docs/javascripts/steel-feature-browser-core.js`:
```js
/*
 * steel-feature-browser-core.js — pure, DOM-free model + matching for the
 * Feature page's merged Source/subclass facet.
 * UMD: exports for node:test, attaches to window.SCFeatureBrowserCore in the
 * browser. Loaded BEFORE steel-feature-browser.js in mkdocs.yml.
 *
 * The Source facet is one OR-group: a class chip (klass) or a class-scoped
 * subclass chip (klass + SUB_SEP + subclass). Subclass names are not globally
 * unique (divine domains repeat across Censor/Conduit), so selection is scoped
 * to the parent class via the composite key.
 */
;(function (root, factory) {
  if (typeof module === "object" && module.exports) {
    module.exports = factory();
  } else {
    root.SCFeatureBrowserCore = factory();
  }
})(typeof self !== "undefined" ? self : this, function () {
  "use strict";

  var SUB_SEP = "§";
  // source → grouping rank for the Source facet (class first, then ancestry/kit/other).
  var SRC_RANK = { class: 0, ancestry: 1, kit: 2, other: 3 };

  function subKey(klass, subclass) { return String(klass) + SUB_SEP + String(subclass); }

  function subsOf(item) {
    var v = item.subclass;
    if (v == null || v === "") return [];
    return Array.isArray(v) ? v : [v];
  }

  function buildSourceModel(items) {
    var srcOf = {};   // klass -> source
    var subSet = {};  // klass -> { subclass: true }
    items.forEach(function (it) {
      if (!it.klass) return;
      if (!(it.klass in srcOf)) srcOf[it.klass] = it.source || "other";
      subsOf(it).forEach(function (s) {
        (subSet[it.klass] = subSet[it.klass] || {})[s] = true;
      });
    });
    var klasses = Object.keys(srcOf).sort(function (a, b) {
      return (SRC_RANK[srcOf[a]] || 9) - (SRC_RANK[srcOf[b]] || 9) || a.localeCompare(b);
    });
    var classes = [], plain = [];
    klasses.forEach(function (k) {
      var subs = subSet[k]
        ? Object.keys(subSet[k]).sort(function (a, b) { return a.localeCompare(b); })
        : [];
      if (srcOf[k] === "class" && subs.length) classes.push({ klass: k, subclasses: subs });
      else plain.push({ klass: k, source: srcOf[k] });
    });
    return { classes: classes, plain: plain };
  }

  function matchesSource(item, selKlass, selSub) {
    selKlass = selKlass || {};
    selSub = selSub || {};
    if (!Object.keys(selKlass).length && !Object.keys(selSub).length) return true;
    if (selKlass[item.klass]) return true;
    var subs = subsOf(item);
    for (var i = 0; i < subs.length; i++) {
      if (selSub[subKey(item.klass, subs[i])]) return true;
    }
    return false;
  }

  return {
    SUB_SEP: SUB_SEP,
    SRC_RANK: SRC_RANK,
    subKey: subKey,
    buildSourceModel: buildSourceModel,
    matchesSource: matchesSource
  };
});
```
